# SDK、流式输出与 Tool Calling

> AtlasCloud 内部产品文档；文档 ID：`sdk-streaming-tools-v3`。

## Base URL

官方 SDK 默认 API base URL 为 https://api.atlascloud.example/v1。自定义代理时必须保留 /v1 路径、Authorization Header 和 request_id 响应头；不要把控制台网页地址当作 API 地址。

## 流式断线

流式连接在收到任何输出前断开，可使用相同 Idempotency-Key 重试一次。收到首个输出后断开，应先按 request_id 查询最终状态；只有状态明确为 not_started 或 failed_before_charge 才可安全重放，避免重复计费。

## Tool Calling Schema

Tool Calling 接受 JSON Schema 的 object、properties、required、enum、数组和有限嵌套。拒绝递归 $ref、oneOf、anyOf、patternProperties、远程引用和可执行描述。服务端仍须独立校验工具参数，模型生成的参数不构成授权。

## Tool Call 回传示例

```json
{"role":"tool","tool_call_id":"call_01","content":{"status":"ok","resource_version":"3"}}
```

每个 call_id 必须恰好对应一个 Observation；错误 Observation 同样需要回传，模型才能重新规划。

## 可复现案例

### 案例 1：Base URL

触发信号是“SDK 初始化连接 AtlasCloud”。受理后先收集环境、API 版本和代理路径，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：使用 https://api.atlascloud.example/v1。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：控制台网页地址不是 API 地址。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 2：首 token 前断线

触发信号是“连接建立后未收到内容”。受理后先收集request_id、幂等键和状态，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：确认 not_started 后最多重试一次。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：状态未知不能换键重放。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 3：首 token 后断线

触发信号是“已收到部分输出”。受理后先收集计费状态、流序号与 request_id，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：查询最终状态并按需续问。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：自动完整重发可能重复计费。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 4：并行 Tool Calls

触发信号是“模型一次返回多个无依赖调用”。受理后先收集每个 call_id、参数 Schema 与预算，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：逐个校验并全部回传 Observation。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：有依赖的调用不得假装可并行。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 5：Schema failure

触发信号是“模型返回额外字段或错误枚举”。受理后先收集原始 call_id 与验证错误码，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：返回结构化 invalid_input 并允许一次修正。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：不得直接执行看起来合理的参数。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 6：代理缓冲

触发信号是“反向代理导致流式内容成块到达”。受理后先收集buffering、timeout 与压缩配置，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：关闭响应缓冲并保留心跳。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：不能只提高客户端读取超时。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

## 操作检查清单

- **Base URL**：确认触发条件确实是“SDK 初始化连接 AtlasCloud”；逐项取得环境、API 版本和代理路径；把“使用 https://api.atlascloud.example/v1”写成可验证步骤；在提交前再次检查“控制台网页地址不是 API 地址”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **首 token 前断线**：确认触发条件确实是“连接建立后未收到内容”；逐项取得request_id、幂等键和状态；把“确认 not_started 后最多重试一次”写成可验证步骤；在提交前再次检查“状态未知不能换键重放”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **首 token 后断线**：确认触发条件确实是“已收到部分输出”；逐项取得计费状态、流序号与 request_id；把“查询最终状态并按需续问”写成可验证步骤；在提交前再次检查“自动完整重发可能重复计费”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **并行 Tool Calls**：确认触发条件确实是“模型一次返回多个无依赖调用”；逐项取得每个 call_id、参数 Schema 与预算；把“逐个校验并全部回传 Observation”写成可验证步骤；在提交前再次检查“有依赖的调用不得假装可并行”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **Schema failure**：确认触发条件确实是“模型返回额外字段或错误枚举”；逐项取得原始 call_id 与验证错误码；把“返回结构化 invalid_input 并允许一次修正”写成可验证步骤；在提交前再次检查“不得直接执行看起来合理的参数”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **代理缓冲**：确认触发条件确实是“反向代理导致流式内容成块到达”；逐项取得buffering、timeout 与压缩配置；把“关闭响应缓冲并保留心跳”写成可验证步骤；在提交前再次检查“不能只提高客户端读取超时”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
