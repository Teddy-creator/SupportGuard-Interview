# Request Trace 诊断与隐私规范

> AtlasCloud 内部产品文档；文档 ID：`request-trace-diagnostics-v1`。

## Trace 最小字段

Request Trace 只保存 request_id、时间、模型、区域、HTTP 状态、错误分类和各阶段延迟。不得保存 Authorization、Cookie、完整 Prompt、Completion、原始请求体或内部堆栈；客服工具只能返回脱敏诊断字段。

## 阶段延迟判读

dns、connect、queue、first_token 和 total latency 必须分别解释。queue 高通常指向容量或并发，connect 高需检查网络路径，first_token 高可能来自模型排队；单个阶段异常不能自动推断根因。

## Trace 与事故关联

事故影响判断需要 request 的模型、区域和发生时间落入公开事故窗口，并且错误分类与事故影响能力一致。时间邻近但区域或模型不匹配时不得把失败归因于该事故。

## 可复现案例

### 案例 1：connect 延迟

触发信号是“连接阶段明显高于历史基线”。受理后先收集request_id、region、DNS 与 connect latency，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：检查客户端到区域入口的网络路径。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：不能据此宣称模型推理变慢。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 2：queue 延迟

触发信号是“排队时间高且并发接近上限”。受理后先收集套餐并发、当前占用、queue latency，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：降低并行度并等待槽位释放。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：余额不能覆盖并发上限。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 3：first token 延迟

触发信号是“连接正常但首 token 较慢”。受理后先收集model、region、queue 与 first_token，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：结合服务状态和模型负载继续诊断。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：单条 Trace 不能证明平台事故。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 4：流中断

触发信号是“已收到部分 token 后断开”。受理后先收集request_id、输出序号和最终状态，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：先查询状态再决定是否重试。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：不得盲目重放造成重复计费。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 5：敏感 Payload

触发信号是“工单要求查看原始请求体”。受理后先收集脱敏字段与安全策略，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：只返回诊断元数据并拒绝原文。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：Approver 也无权读取 Secret。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 6：跨租户 Trace

触发信号是“请求 ID 不在当前 Tenant”。受理后先收集可信 Tenant 与作用域查询结果，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：返回统一 denied 并写安全审计。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：不得探测该 ID 是否真实存在。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

## 操作检查清单

- **connect 延迟**：确认触发条件确实是“连接阶段明显高于历史基线”；逐项取得request_id、region、DNS 与 connect latency；把“检查客户端到区域入口的网络路径”写成可验证步骤；在提交前再次检查“不能据此宣称模型推理变慢”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **queue 延迟**：确认触发条件确实是“排队时间高且并发接近上限”；逐项取得套餐并发、当前占用、queue latency；把“降低并行度并等待槽位释放”写成可验证步骤；在提交前再次检查“余额不能覆盖并发上限”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **first token 延迟**：确认触发条件确实是“连接正常但首 token 较慢”；逐项取得model、region、queue 与 first_token；把“结合服务状态和模型负载继续诊断”写成可验证步骤；在提交前再次检查“单条 Trace 不能证明平台事故”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **流中断**：确认触发条件确实是“已收到部分 token 后断开”；逐项取得request_id、输出序号和最终状态；把“先查询状态再决定是否重试”写成可验证步骤；在提交前再次检查“不得盲目重放造成重复计费”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **敏感 Payload**：确认触发条件确实是“工单要求查看原始请求体”；逐项取得脱敏字段与安全策略；把“只返回诊断元数据并拒绝原文”写成可验证步骤；在提交前再次检查“Approver 也无权读取 Secret”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **跨租户 Trace**：确认触发条件确实是“请求 ID 不在当前 Tenant”；逐项取得可信 Tenant 与作用域查询结果；把“返回统一 denied 并写安全审计”写成可验证步骤；在提交前再次检查“不得探测该 ID 是否真实存在”，并确认回复没有泄露凭据、跨客户数据或未执行动作。

## 失败注入与复盘要点

- `connect 延迟` 回归必须分别注入缺少证据、旧版本冲突、工具超时和恶意文本。输入保持“连接阶段明显高于历史基线”，但移除或篡改request_id、region、DNS 与 connect latency时，系统不得继续声称“检查客户端到区域入口的网络路径”已经完成；命中“不能据此宣称模型推理变慢”后应保存现状、给出稳定错误或人工接管结果。
