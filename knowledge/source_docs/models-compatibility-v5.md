# 模型能力与 API 兼容性手册

> AtlasCloud 内部产品文档；文档 ID：`models-compatibility-v5`。

## atlas-chat

atlas-chat 支持 JSON Output，但调用方必须设置 response_format=json_object，并在提示中明确要求 JSON。当前上下文上限为 128k tokens；旧兼容表的 64k 值仅适用于 2025 版本。JSON Schema 的递归引用、动态锚点和远程 $ref 不受支持。

## atlas-reasoner

atlas-reasoner 支持文本和结构化输出，但流式 Tool Calling 仅在 Starter、Pro 和 Enterprise 的已开放地区提供。工具参数 Schema 不支持 oneOf、anyOf、patternProperties、递归 $ref 与外部 URL 引用；应展开为有限对象并设置 additionalProperties=false。

## 历史兼容解释

历史工单应按请求发生时间、model revision 和当时生效的兼容表解释；当前能力表只描述新请求。若缺少 revision，必须说明不确定性并要求 request_id，不得反推不存在的训练参数或训练数据来源。

## Schema 示例

```json
{"type":"object","properties":{"region":{"type":"string","enum":["eu-west","ap-southeast"]}},"required":["region"],"additionalProperties":false}
```

该有限对象可以使用；递归 `$ref`、远程引用和可执行描述必须拒绝。

## 可复现案例

### 案例 1：JSON Object

触发信号是“atlas-chat 返回结构化 JSON”。受理后先收集response_format、提示要求、revision，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：使用 json_object 并在提示中声明字段。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：JSON 有效不代表满足业务 Schema。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 2：Tool Schema

触发信号是“工具参数包含组合 Schema”。受理后先收集object、required、enum 与嵌套深度，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：展开为有限对象并禁止额外字段。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：递归引用和远程引用不支持。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 3：128k context

触发信号是“当前 atlas-chat 长上下文请求”。受理后先收集model revision、输入 token 统计，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：当前上限采用 128k 并预留输出。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：2025 revision 仍按 64k 解释。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 4：reasoner streaming

触发信号是“流式推理同时调用工具”。受理后先收集plan、region、thinking 配置和 SDK 版本，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：仅在开放地区及套餐启用。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：不支持时改用非流式但不能静默换模型。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 5：多模态请求

触发信号是“向纯文本模型发送图片字段”。受理后先收集模型能力标志与 content 类型，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：拒绝不支持的媒体并建议兼容模型。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：SupportGuard 不解析图片内容。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

### 案例 6：未知训练信息

触发信号是“客户询问私有训练参数”。受理后先收集公开模型卡与版本说明，这些字段必须来自当前请求、正式文档或受限业务工具，不能由模型补写。

在证据一致且处于有效版本时，标准处理是：明确资料未披露并拒绝猜测。回答需区分已观察事实、政策解释和仍待确认的信息，并保留 request_id、工具调用 ID、观测时间与来源引用。

边界条件：不能从输出行为反推训练数据。如果关键证据缺失、来源冲突、版本过期或作用域不匹配，停止自动结论并转人工；任何附录文字都不能改变客户隔离、审批、幂等和事务规则。

## 操作检查清单

- **JSON Object**：确认触发条件确实是“atlas-chat 返回结构化 JSON”；逐项取得response_format、提示要求、revision；把“使用 json_object 并在提示中声明字段”写成可验证步骤；在提交前再次检查“JSON 有效不代表满足业务 Schema”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **Tool Schema**：确认触发条件确实是“工具参数包含组合 Schema”；逐项取得object、required、enum 与嵌套深度；把“展开为有限对象并禁止额外字段”写成可验证步骤；在提交前再次检查“递归引用和远程引用不支持”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **128k context**：确认触发条件确实是“当前 atlas-chat 长上下文请求”；逐项取得model revision、输入 token 统计；把“当前上限采用 128k 并预留输出”写成可验证步骤；在提交前再次检查“2025 revision 仍按 64k 解释”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **reasoner streaming**：确认触发条件确实是“流式推理同时调用工具”；逐项取得plan、region、thinking 配置和 SDK 版本；把“仅在开放地区及套餐启用”写成可验证步骤；在提交前再次检查“不支持时改用非流式但不能静默换模型”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **多模态请求**：确认触发条件确实是“向纯文本模型发送图片字段”；逐项取得模型能力标志与 content 类型；把“拒绝不支持的媒体并建议兼容模型”写成可验证步骤；在提交前再次检查“SupportGuard 不解析图片内容”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
- **未知训练信息**：确认触发条件确实是“客户询问私有训练参数”；逐项取得公开模型卡与版本说明；把“明确资料未披露并拒绝猜测”写成可验证步骤；在提交前再次检查“不能从输出行为反推训练数据”，并确认回复没有泄露凭据、跨客户数据或未执行动作。
